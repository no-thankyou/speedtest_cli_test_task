# speedtest-cli (тестовое задание)

Скрипт замеряет скорость загрузки с вашего компьютера до указанного URL. Он выполняет
N (по умолчанию 10) **последовательных** HTTP-запросов к адресу тяжёлого файла,
дожидается полного скачивания каждого и печатает:

- среднее время запроса (плюс медиана, min, max, стандартное отклонение);
- объём скачанных данных;
- средний TTFB (задержку до первого байта);
- итоговую скорость в **Mbit/s** и **MB/s**.

## Требования

- Python 3.10+
- `requests`

## Установка

```bash
git clone https://github.com/no-thankyou/speedtest_cli_test_task.git
cd speedtest_cli_test_task
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
python speedtest.py https://proof.ovh.net/files/10Mb.dat
```

Опции:

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-n`, `--count N` | `10` | число последовательных запросов |
| `-t`, `--timeout SEC` | `30` | таймаут на подключение и на паузу между чанками данных |
| `--no-keepalive` | выкл. | новое соединение (DNS + TCP + TLS) на каждый запрос |
| `--warmup` | выкл. | прогревочный запрос, не входящий в статистику |
| `--no-cache-bust` | выкл. | не добавлять уникальный query-параметр и `no-cache` заголовки |
| `-V`, `--version` | | версия |

Коды выхода: `0` — есть хотя бы один успешный запрос, `1` — все запросы неуспешны,
`2` — неверные аргументы, `130` — прервано по Ctrl+C (статистика по завершённым
запросам всё равно печатается).

Пример вывода:

```

Запросов: 3, режим: новое соединение на запрос

Прогревочный запрос (не входит в статистику): ok
#1    10.49 MB    3.533 s  TTFB    387 ms     23.74 Mbit/s
#2    10.49 MB    4.760 s  TTFB    381 ms     17.62 Mbit/s
#3    10.49 MB    2.154 s  TTFB    379 ms     38.95 Mbit/s

Успешных запросов:     3/3
Скачано всего:         31.46 MB (31457280 байт)
Среднее время запроса: 3.482 s (медиана 3.533, min 2.154, max 4.760, σ 1.304)
Средний TTFB:          382 ms
Скорость передачи тела (без TTFB): 27.06 Mbit/s

```

Подходящие адреса для проверки — файлы от 10 МБ и больше, например:

- `https://proof.ovh.net/files/10Mb.dat`, `https://proof.ovh.net/files/100Mb.dat`
- `https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg` (JPEG ~14.7 МБ;
  при частых запросах Wikimedia отвечает `429`, см. ниже)

## Методика и принятые решения

**Что измеряется.** Скорость загрузки конкретного файла с конкретного сервера по одному
TCP-соединению. Это не то же самое, что «скорость интернета»: результат ограничен самым
узким местом цепочки (ваш канал, маршрут, сервер/CDN). Сервисы вроде Speedtest качают
в несколько параллельных потоков с ближайшего сервера, поэтому их цифры обычно выше.
По заданию запросы идут последовательно, поэтому здесь один поток.

**Как считается итоговая скорость.** `Σ байт / Σ времени` по успешным запросам.
Среднее арифметическое скоростей отдельных запросов считать **нельзя**: оно завышает
результат, если запросы длились разное время. Пример: 10 МБ за 1 с и 10 МБ за 9 с —
среднее скоростей 5.56 МБ/с, а реальная скорость 20 МБ / 10 с = 2 МБ/с. Этот случай
покрыт тестом.

**Время запроса и TTFB.** Время каждого запроса — от отправки до получения последнего
байта тела. В него входят DNS, TCP/TLS-рукопожатие, ожидание ответа сервера (TTFB)
и передача тела. На маленьких файлах основную часть времени занимает задержка, и
скорость получается заниженной, поэтому нужен тяжёлый файл. Скрипт отдельно показывает
TTFB и «скорость передачи тела» (`Σ байт / Σ(время − TTFB)`), то есть пропускную
способность без учёта задержки.

**Единицы.** «мб/с» можно понять по-разному, поэтому выводятся оба значения:
мегабиты (`Mbit/s`, в них меряют провайдеры) и мегабайты (`MB/s`), разница в 8 раз.
Префиксы десятичные: 1 MB = 10⁶ байт.

**Соединение.** По умолчанию соединение переиспользуется (keep-alive). Первый запрос
тогда «холодный» (DNS + TLS), это видно по его TTFB. `--warmup` исключает этот эффект,
`--no-keepalive` наоборот включает рукопожатие в каждый замер.

**Кэши и сжатие.**
- К URL добавляется уникальный параметр `_speedtest=<uuid>` и заголовки
  `Cache-Control: no-cache`, чтобы ответ не пришёл из кэша прокси/CDN. Отключается
  флагом `--no-cache-bust`: это нужно, если сервер не принимает лишние параметры или
  если вы хотите мерить именно отдачу с CDN.
- Отправляется `Accept-Encoding: identity`, а байты считаются «сырыми»
  (`decode_content=False`). Если сервер всё же пришлёт сжатое тело, считаются реально
  переданные по сети байты, а не распакованные.

**Корректность скачивания.**
- Тело читается потоково чанками по 64 КБ и не держится в памяти, поэтому файл может
  быть любого размера.
- Байты считаются вручную, без опоры на `Content-Length` (его может не быть при
  chunked-передаче). Если заголовок есть и не совпал с полученным объёмом, запрос
  считается неуспешным (обрыв).
- Время меряется `time.perf_counter()`: монотонные часы, на них не влияет подстройка
  системного времени.

**Ошибки.** Ответ не 2xx, таймаут, обрыв, отказ в соединении, пустое тело: запрос
помечается как `FAILED` с причиной, статистика считается по успешным (`Успешных
запросов: 7/10`). Выставлен собственный `User-Agent`: часть серверов отвечает 403
на запросы без него. Прокси берутся из переменных окружения (`HTTPS_PROXY` и т.п.),
как это делает `requests`.

**Rate limiting.** Некоторые хостинги ограничивают частоту скачивания больших файлов.
Например, Wikimedia после нескольких полных загрузок оригинала подряд отвечает
`429 Too Many Requests`. Скорее всего, это усугубляет cache-busting: запросы идут
мимо CDN на origin. Скрипт корректно обрабатывает такой случай, но для замера лучше
брать специальные тестовые файлы (OVH и т.п.).

**Ограничения.**
- Один поток: широкий канал (сотни Мбит/с и выше) может быть недогружен.
- Результат сильно зависит от удалённости и загрузки сервера.
- Upload не измеряется.

## Тесты

Тесты не ходят в интернет: они поднимают локальный HTTP-сервер и проверяют подсчёт
байтов, chunked-ответы без `Content-Length`, обрыв тела, HTTP-ошибки, отказ
в соединении, прогрев, cache-busting, расчёт статистики и коды выхода CLI.

```bash
pip install -r requirements-dev.txt
pytest
```

## Структура

```
speedtest.py            # CLI и логика замера
tests/test_speedtest.py # тесты на локальном HTTP-сервере
requirements.txt        # runtime-зависимости
requirements-dev.txt    # + pytest
```
